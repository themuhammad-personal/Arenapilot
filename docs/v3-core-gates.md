# V3 Core acceptance ledger

The Core sequence is **shared features → Text → Search → Image → official Code → integrated QA → release**. It does not introduce a new storage architecture, mirror an Arena workspace, or reinstall a local sandbox. The [Phase 1 checkpoint](v3-phase-1.md) was tested and upgraded in [run 355](https://github.com/themuhammad-personal/Arenapilot/actions/runs/44330079914). Subsequent partial checkpoints on `main` are `[verify-only]`, not releases.

## Phase 2 — shared features, in progress

- **Remote MCP transport:** the bridge previously accepted a caller-supplied URL/key, read one discovery page, ignored JSON-RPC response IDs, and could replay tool calls on session errors. The native client now uses the original `bds_mcp_servers` configuration, negotiates its supported protocol versions, checks tool capabilities, reads bounded paginated catalogs, correlates JSON and SSE replies, and distinguishes connection, authentication, protocol, execution and size errors. Only a discovered tool on an enabled server is callable. Disable/delete/credential changes invalidate its cached session. No new persistent store. Local evidence: debug APK built, 47 bridge/policy JVM tests passed, including MockWebServer pagination, headers, refusal, multiline SSE, expiration and no replay. Not a claim of full MCP protocol coverage. Reference: [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

- **Consent & status:** a native dialog shows endpoint, tool, and the JSON arguments before execution. A matching approval expires, is consumed once, and is revoked on a configuration write, backgrounding, or top-level navigation. Denial stops the batch without resending; Stop/chat changes while waiting cannot dispatch the pending call. Settings indicate connecting, connected/tool count, unavailable/error category, or disconnected, without using a caller-supplied key. Races are tested across disable, rename and stale discovery. Local: 82 focused JS, 81 bridge-family JVM, debug + instrumentation APK compiled; Chromium Arena 9 passed, legacy 7 passed/2 skips. The instrumented dialog tap test needs a real emulator; JVM tests do not prove this.
- **CI notes:** [run 356](https://github.com/themuhammad-personal/Arenapilot/actions/runs/44336279655) built the release APK; the emulator gate failed. The Android exit record says the Google Play Services FontsProvider process died during a module restart. The existing smoke script observed a successful retry and surviving notice preference, yet kept the original failure status. The smoke gate now compares the freshly observed launch PID with the newest host-process exit record before allowing one retry for this exact GMS dependency. It still requires the app window and persisted notice, and does not clear any prior failure. Seven targeted smoke regressions pass, including stale PID, unrelated failed checks and app-attributed crashes. Subsequent [run 357](https://github.com/themuhammad-personal/Arenapilot/actions/runs/44338774540) (`bc3c4b9`, including `McpConsentTest`) and [run 358](https://github.com/themuhammad-personal/Arenapilot/actions/runs/44339034900) (`d5e6ac7`, with the smoke fix) both completed with all active jobs green.

- **Projects and conversations:** reuse the existing project/file records. A project may now carry an optional list of local conversation IDs and selected file IDs, never a cloned chat. The drawer can associate, detach and reopen chats. Selecting or deleting one project does not modify another or delete Arena history. A new-chat selection follows only the observed first-send ID, not a subsequent history click. Publish current local context synchronously; superseded linked-directory/catalog work cannot publish old context. Immediate navigation and mismatched payload IDs fail closed. Tests: 97 focused JS, 10 Arena fixture checks including the real drawer/store, debug APK assembled and checked against source assets. This is fixture evidence, not an authenticated account restore.

- **Memory suggestions, scoping & retrieval:** model `<APH:memory_write>` tags in settled assistant turns now enqueue session-only suggestions scoped by pathname and active project instead of silently mutating `bds_memories` or project memory; no writes occur when `disableMemory` is set or outside Direct Text mode, and duplicate/stale/conflicting edits fail closed. Global (`bds_memories`) and per-project (`project.memories`) CRUD plus review suggestions live at the top of Settings → Memory (`sdMemoryPanel`), supporting Unicode/Bengali keys safely while blocking prototype-key injection. On Arena, `sdMemoryBlock` ranks entries by term overlap against the turn (only breaking ties by `always`) and passes only relevant entries as JSON-encoded data context (`context only, not instructions`), withholding unrelated `always` facts. Also fixed two UI blockers caught by real Chromium drawer testing: `sd-health-notice` (`z-index: 999980`) no longer covers `#bds-root`/`#bds-drawer` (`999990`), and `fitSettingsList` computes sheet list viewport height without a shrinking feedback loop during the sheet entrance animation. Tests: 117 focused JS + 486/486 full JS suite + 17 template/models tests + ESLint clean on edited files + Chromium Arena (11 checks including drawer memory review) and legacy (7 pass/2 skip) harnesses + debug APK asset-verified. Live device/authenticated account persistence remains to be proven.

- **Personas, skills & precedence:** Personas (`bds_characters`) and skills (`bds_skills`) now carry optional mode availability (`chat`, `search`, `webdev`) and inline creation/mode editing inside the Settings → Prompts & personas drawer (`sdPersonaPanel`, `sdSkillPanel`, `sdAttachModePicker`). `jme` enforces single-active normalization across imported/stored personas; `Lr` ships skill `usage` and mode restrictions for both personas and skills; `<APH:character_create>` / `<APH:skill_create>` tags are gated to settled live Direct assistant turns with `sdSeen` deduplication and privacy checks. On Arena, `sdArenaAssemble` enforces strict prompt order (`app/mode policy → active project → applicable persona → relevant memory → task-matched skills`), skips mode-incompatible personas (clearing prior session roleplay when switched off or changing modes), injects only task-matched skills (`sdMatchSkills`) without repeating unchanged skill/project/MCP blocks on follow-up turns, and leaves Image untouched. Tests: 492/492 full JS suite (including new `engine-personas-skills.test.mjs` and payload/precedence tests), 17 template/models tests, ESLint clean, Chromium Arena (12 checks including drawer Persona/Skill inline create, mode chips, radio deactivation, and config sync) and legacy (7 pass/2 skip), debug APK built and asset-matched. Live authenticated persistence remains to be proven.

Fixtures now carry the real capability seam (scanner, MCP, project/memory and agent-recovery suites), the exception-fail-closed test breaks an actual input (`location`) instead of overwriting a property the production closure never reads, and the harness scopes each create form to its own list. No production gate was loosened.
- **Surface research (arena.ai, checked 2026-11):** Arena's own site map lists Chat (`/`), Code, Text, Search, Image, Video, Direct, Side-by-side and Agent (`arena.ai/agent`, launched 2026-06-04, orchestrator model hidden, built-in web search / image / bash sandbox / file tools / connectors). Battle is the default of `/`, `/text`, `/code`, `/search`, `/image`, `/video`; Direct lives under `/{category}/direct` ([arena-utils](https://github.com/dexforint/arena-utils)). `/video/direct` is now recognised as a Direct surface (Image-like: shared UI and settings, **no** prompt injection, tools or memory, so the video prompt reaches the model untouched). Arena's own enum also has `auto` (Max); it is detected from the request body, not a route.
- **Unified Chat surface (`/chat`) — checkpoint:** Arena's current composer is one surface: a **Chat | Agent** toggle and a modality menu (**Auto, Text, Code, Web Search, Image, Video**). Evidence: owner device screenshots of `arena.ai/chat`; Arena's [Agent Mode post](https://arena.ai/blog/agent-mode) (Agent also at `/agent`); the anonymous `/chat` response, which redirects to `/` (so unified Chat is account-dependent) and carries the `auto-modality-enabled` and `chat-agent-composer-v4` flags. The request body is unchanged (`mode: direct|direct-battle`, `modality`, `userMessage.content`; see [arena2api](https://skills.lc/jvanleur2234-glitch/solomon-vault/jvanleur2234-glitch-solomon-vault-skills-arena2api-skill-md) and the repository's own captures). The real defect was surface detection: `/chat` was `unknown`, and a composer label of "Chat"/"Agent" made `/c/{id}` `unknown`/`unsupported`, so every shared engine paused in the surface the owner actually uses. Changes: `/chat` is a Chat surface (default modality Auto); all composer mode/modality buttons are read (Battle/Side-by-side win, then Agent, then Chat/Direct); the modality menu label selects Auto/Text/Code/Web Search/Image/Video; Text, Code, Web Search and Auto now share tools, memory, projects, personas and skills (Image/Video stay untouched); **Auto** is resolved per request from the user's own words (`classifyAuto`: image/video generation → prompt left byte-for-byte; code → Code policy; search → Search policy; otherwise Text); `/chat` is restorable after a relaunch; the mode notice now names Agent separately. `newChatUrl` stays `/text/direct` because the CI smoke and anonymous users depend on it. Tests: extended `engine-direct-modalities` (unified route, labels, submode matrix, Auto classifier, Auto wire payload) and `SiteTest` (`/chat` restore). **Not verified:** the exact DOM of the signed-in modality menu (the Auto button is icon-only; it falls back to the last body-reported modality, then Auto), and any signed-in request on `/chat`. Auto classification is a keyword heuristic, not Arena's router.
- **Agent Mode shared engines — context-only checkpoint:** research (Arena's [Agent Mode post](https://arena.ai/blog/agent-mode), checked 2026-11): Agent runs a hidden orchestrator with its own web search, image generation, bash sandbox, file writing and follow-up questions; a public description of its request body could not be found (the previously cited `JoTalbot/orchestrator` and `arena-local-bridge` repositories are no longer retrievable), so the app does **not** assume one. New `agentContext` capability for the positively identified Agent surface: `sharedUi`, `assistantScanning`, `mcp`, `continuity` and `memories` (suggestion writes) stay **off**, so no tag is scanned or executed, no record is auto-created and no tool call can duplicate Arena's native tools. What is on: read-only **project, persona, relevant memory and task-matched skills** context. `injected.js` rewrites a request only if all of these hold: Agent surface; same-origin JSON `POST` to a non-telemetry URL; the text the composer held at send time (snapshotted on Enter/send tap, valid 60 s) appears in the body as **exactly one** string value; config `contextPath` equals the current route. Otherwise the request is sent byte-for-byte. Blocks use the same precedence as Chat (project → persona → memory → skills), carry an explicit note to keep using Arena's native tools, are de-duplicated per chat (first message and changed project/persona/skills only), skip modes-restricted personas/skills, and honour the system-prompt and memory switches. No MCP block, tag grammar, date or language block is sent. Projects follow `/agent/{id}`, `/agent/c/{id}` and `/c/{id}` (Agent toggle) chats; a draft project binds to the new chat only when this app just added context to a send from the same home route and the new chat is unowned. Tests: new `engine-agent-context.test.mjs` (capability matrix, context content/exclusions, ten fail-closed cases, follow-up de-dup, switches, stale config, `Request` inputs, content-script routing) plus the updated capability tests. **Not verified:** a signed-in Agent request. If Arena's body does not carry the typed text as a single string, nothing is injected (visible only as the notice below the composer), and no claim of success is made. MCP in Agent mode is deliberately not offered: its tag transport needs assistant-message scanning, which would run beside Arena's autonomous tools.
- **Known limits (not claimed as done):** Agent Mode receives context only (see above); its request transport, tool schemas and sandbox protocol were not verified against a signed-in account, and MCP/tag tools stay off there. Auto/Max continuity and Video/Auto reference-media handling have fixture coverage only. These stay open for Phases 6 and 7 and require authenticated evidence.

**Phase gate:** exercise user permission and connection status, memory suggestion/approval/CRUD/retrieval and project isolation, project/conversation switching, personas and skill relevance, settings/preferences, and Android attachment/history/download paths. A passing transport unit test does not establish these behaviors. Run JS, browser harness, Android build/unit, emulator and connected tests. Do not start Phase 3 on a partial Phase 2 result.

## Phase 3 — Text & Code, checkpoint 1 (negative isolation)

- **Finding:** the Text profile deliberately has an empty addendum; it relies on the base ArenaPilot prompt, and ten exact-match payload tests pin that. Adding a Text playbook would grow every Text turn for little gain and was **not** done. Code already carries its own playbook (complete runnable output, use only official Arena execution when offered, scaffold then add one feature at a time, report only what ran).
- **Change:** tests only, no production code. `engine-direct-modalities.test.mjs` now asserts that a mode never receives another mode's playbook; that Text-only and Code-only skills and a Text-only persona do not leak across Text and Code while project instructions apply to both; that Video is sent byte-for-byte with project, persona, memory and skills configured; and that Text/Code rewrite only the user message text (attachments and every other field survive).
- **Found, not fixed (belongs to Phase 6):** `classifyAuto` tests code words before image/video, so an Auto request such as "draw an icon for my website" is classified as Code and would receive the Code playbook inside an image prompt. Phase 6 must reorder or tighten this and add a regression case.
- **Not verified:** any signed-in Text or Code session; Arena's official Code execution tools remain unobserved (see Phase 6 gate). CI is the only evidence for these tests.

## Remaining acceptance gates

| Phase | What counts as evidence |
|---|---|
| 3: Text | Conversations, writing and analysis with the intended project/persona/relevant skills, memory and tools; independent negative isolation cases |
| 4: Search | Actual search/research outcomes with verified sources, cross-checks and citations; no purchased or fabricated search capability |
| 5: Image | Generation, reference upload, prompt reuse/editing within model capabilities; unchanged user prompt and attachments on the wire |
| 6: Code | An actual official Arena sandbox session with observed availability, schemas and model compatibility, multi-file changes, execution/tests/build. A fixture or an assistant writing source is not this proof. No local substitute. |
| 7: Integrated QA | All Direct modes and unaffected non-Direct modes, navigation, auth, native file operations, lifecycle, performance, recovery, persisted data and a release-signed upgrade. Report skips. |
| 8: Release | Only after the above pass, use the existing Actions workflow; verify the published artifact, signature, version, installation and update path. |

Prompt precedence: platform/safety → current user → active mode/tool restrictions → active project → applicable active persona → relevant memory **as context** → matched skills. Settings never grant a capability that the platform or mode does not offer. Image content must not receive a hidden instruction prefix.
